# v0.5.0

harness-bridge now opens a searchable terminal workbench and includes an optional local browser interface built with GPUI Kit. This release also adds Qoder support and imports from official web chat exports.

## Interactive interfaces

Run `harness-bridge` to search and filter saved sessions, read excerpts, preview a migration, and confirm the write. Portable import and export are available in the same interface. The existing CLI commands remain available, with search, limits and JSON output for listings; `providers` and `doctor` explain supported operations and local discovery.

Run `harness-bridge ui --open` for the local browser interface. Its Rust frontend uses GPUI Kit 0.9.0, compiled to WebAssembly, with a session table, source and project filters, conversation excerpts, a transfer inspector, source-location settings and per-tab activity history. The release downloads include both interfaces and bundle their fonts and icons locally. Source builds enable the browser with `--features web-ui`; no frontend compiler is needed to use the checked-in bundle.

Both interfaces capture the source during preview and require a separate write action. Confirmation uses that captured snapshot, checks for destination changes and cannot reuse an already consumed browser plan.

## Qoder and web chat imports

Qoder CLI is a native read/write provider. Its reader follows the committed branch, separates the archive from retained context and preserves saved child links. Qoder IDE hook transcripts and recent desktop histories are read-only sources; importing into Qoder CLI does not populate the IDE sidebar. Unsupported replacement state requires explicit recovery, while incomplete checkpoints fail conversion.

Official ChatGPT, claude.ai and Gemini exports can be read as folders, ZIP archives or supported conversation files. These are sources for local coding sessions. Visible branches, export-provided attachments and provider-specific limits are described in the [migration guide](https://github.com/ahnafnafee/harness-bridge/blob/v0.5.0/docs/migration-guide.md#continue-a-web-chat).

## Branding and documentation

The cobalt-and-silver icon now has transparent exterior corners, including the Windows icon. The README has a compact introduction, direct platform downloads, a provider support table and shorter examples, with the full conversion reference in a separate guide.

## Compatibility and validation

- Qoder IDE writes are unavailable. Qoder CLI 1.1.85 recognized generated sessions in isolated homes; authenticated Qoder continuation has not been verified.
- Windows Chrome is the validated graphical browser. Screen-reader integration and real phone keyboard/IME behavior remain unverified.
- Antigravity writes remain text-only; tool activity stays in the normalized archive. Hidden model state and encrypted decisions cannot be recovered.
- Portable files containing Qoder sessions require harness-bridge 0.5.0 or newer on the receiving computer.

Validation includes 95 Rust tests, four GPUI model tests, strict Clippy, bundle checksums, command-only and browser-only builds, browser interaction checks and the existing 16-direction portable transfer matrix. Release packaging also checks archive contents, executable architecture, version and the local UI API against temporary stores on Windows x64, Linux x64 and macOS Apple Silicon. Native Codex continuation probes use a local Responses stub; validation makes no remote model requests.

See the [interface guide](https://github.com/ahnafnafee/harness-bridge/blob/v0.5.0/docs/interfaces.md) for controls and browser requirements, and [development](https://github.com/ahnafnafee/harness-bridge/blob/v0.5.0/docs/development.md) for reproducible checks.
