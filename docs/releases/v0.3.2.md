### Changes

- Support native Codex `agent_message` model-input records in retained checkpoints, later turns and readable archives. Plaintext agent mail becomes labeled external input with its author and recipient, so destination harnesses preserve the message without requiring native agent delivery.
- Export sessions containing encrypted agent-message payloads through the existing portable v2 recovery path. Preserve readable headers, mark unavailable payloads explicitly and require `--rebuild-resume-context` on import/migration, including when the source has never been compacted. Encrypted payloads are not replayed or represented as complete plaintext.
- Keep reading later checkpoint items and turns after encountering unavailable encrypted state. Unknown or malformed active records still fail before conversion; their error now explains that reconstruction cannot safely skip them. Similar assistant UI notifications remain separate and are not duplicated.

- Resolve chosen Codex desktop names ahead of initial-prompt titles in modern registries, with fallback for older schemas and empty registry entries.

Upgrade the source machine to 0.3.2, then retry the same export command. Existing portable v1/v2 files remain supported, and the normalized output remains compatible with 0.3.1 receivers. Files marked with unavailable context still require explicit recovery on the destination machine:

```sh
harness-bridge import session.hbridge.json --to codex --rebuild-resume-context --prune-resume-context
```
