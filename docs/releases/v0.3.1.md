### Changes

- Allow exporting readable Codex session history when encrypted compaction prevents complete retained-context reconstruction. Saved descendants and parent links remain transferable; encrypted hidden state is omitted.
- Add `--rebuild-resume-context` for import and migration. Recovery uses readable items from the latest checkpoint and later turns, falling back to the readable archive when that seed is unavailable. A recovery notice describes the missing state, and the usual whole-family context budget and explicit pruning still apply before writes.
- Emit portable format version 2 only for files requiring this recovery. Version 0.3.0 receivers reject them explicitly; ordinary version 1 files remain supported. Upgrade both machines to 0.3.1 before transferring encrypted-compaction sessions.
- Preserve Codex custom tool calls, their original inputs, and structured text outputs in the readable archive. Resolve Codex session titles from the local index and read-only desktop registry so export can select named chats.
- Keep unknown or malformed active items as errors rather than allowing an encrypted checkpoint to hide them.

Export on the source machine as usual:

```sh
harness-bridge export "<session-id-or-title>" --from codex --output session.hbridge.json --include-subagents
```

Copy the file to the receiving machine, initialize its destination harness, and explicitly recover unavailable context:

```sh
harness-bridge import session.hbridge.json --to codex --cwd "/path/to/project" --rebuild-resume-context --prune-resume-context --dry-run
harness-bridge import session.hbridge.json --to codex --cwd "/path/to/project" --rebuild-resume-context --prune-resume-context
```

Recovery preserves readable history but cannot recover decisions or reasoning available only in encrypted state. Verify the current task before continuing. Project files and attachments still transfer separately; repeated imports can overwrite later destination turns.
